# Product requirements

These IDs are the stable source for acceptance work.

| ID        | Requirement                                                                                                                                                                                                                                                         | Main implementation                                                                           |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| TEN-01    | Support multiple independent businesses and salons; each salon has one location initially.                                                                                                                                                                          | `businesses`, `salons`, business-scoped relations and RLS                                     |
| TEN-02    | One shared WhatsApp number lists every active salon. If only one is active, customer choice is skipped; with several, selection is required.                                                                                                                        | conversation catalog and draft selection                                                      |
| ROLE-01   | Customers, owners, and technicians use WhatsApp only. Platform admins use the web dashboard.                                                                                                                                                                        | verified contact mappings and `/admin`                                                        |
| SETUP-01  | Admin creates initial business/salon data and assigns one or more owner WA IDs. Services and technicians are optional.                                                                                                                                              | admin CRUD and `business_owners`                                                              |
| SETUP-02  | Owners may later update salon information, services, technician records, and the technician-choice setting through natural chat.                                                                                                                                    | scoped owner function tools                                                                   |
| BOOK-01   | A booking needs an active salon and a future start time; it auto-confirms.                                                                                                                                                                                          | `create_booking` tool and database RPC                                                        |
| BOOK-02   | Capacity, duration, attendance, pricing, service configuration, and technician assignment never block booking.                                                                                                                                                      | flexible schema and prompt/tool validation                                                    |
| BOOK-03   | One booking supports several services, Other/custom service text, and an optional additional request.                                                                                                                                                               | `booking_services` snapshots and booking request                                              |
| BOOK-04   | `technician_ref` may be null, stale, or unresolved. Recorded time off guides choices but never blocks or cancels.                                                                                                                                                   | soft UUID and prompt catalog                                                                  |
| BOOK-05   | The same customer may cancel a confirmed booking before its start time. Cancellation remains in analytics.                                                                                                                                                          | `cancel_customer_booking` RPC                                                                 |
| CHAT-01   | Customers can express salon, service, and date/time naturally, use controls, or mix both.                                                                                                                                                                           | OpenAI function calling and WhatsApp interactive replies                                      |
| CHAT-02   | The app owns bounded conversation history and executes validated, idempotent tools.                                                                                                                                                                                 | conversations/messages/tool executions                                                        |
| LANG-01   | Landing page is always German and admin dashboard always English.                                                                                                                                                                                                   | separate root layouts                                                                         |
| LANG-02   | All WhatsApp and AI replies use `BOT_LOCALE=en                                                                                                                                                                                                                      | de`, fixed until redeployment. Dashboard greeting text can be edited without changing locale. | bot dictionaries, prompt, settings |
| GREET-01  | A contact's first conversation receives the configured simple greeting and helpful controls.                                                                                                                                                                        | atomic `greeted_at` claim and outbox                                                          |
| AI-01     | A customer can send a hand/nail image and request up to three style previews. Default limit is three requests per platform day per contact.                                                                                                                         | preview quota RPC and OpenAI image edit                                                       |
| AI-02     | Application infrastructure never persists image bytes. WhatsApp/OpenAI provider retention is separate.                                                                                                                                                              | memory-only pipeline and media-ID fields                                                      |
| OWNER-01  | Owners see business-scoped booking summaries/customer records and cannot browse other businesses.                                                                                                                                                                   | owner mappings and scoped tool queries                                                        |
| TECH-01   | Technicians receive assignment/cancellation notifications, see only assigned bookings, and may record optional time off.                                                                                                                                            | technician tools and message outbox                                                           |
| ADMIN-01  | English Ant Design dashboard can CRUD business data, manage defaults, inspect analytics/health, and export booking reports. Browser API work uses SWR.                                                                                                              | admin pages and `/api/admin/*`                                                                |
| ADMIN-02  | The migration creates `admin@gmail.com` / `Pass1234`. The admin UI requires a password change before other pages; subsequent passwords live in Supabase Auth.                                                                                                       | auth migration, admin shell, account API                                                      |
| METRIC-01 | Report total, currently confirmed, cancelled, distinct booking customers, returning customers, and trends by day/week/month. Do not infer attendance or invoices.                                                                                                   | analytics calculator/dashboard/CSV                                                            |
| OPS-01    | Local/dev/prod use isolated credentials and empty business data. Supabase's GitHub integration applies versioned migrations.                                                                                                                                        | `.env.example`, Supabase integration, quality workflow                                        |
| SIM-01    | An env-gated, admin-authenticated web simulator works locally and when hosted, alongside real WhatsApp. Admins add/remove customer windows requiring name and WA ID; owner/technician windows use stored mappings.                                                  | `/admin/simulator`, `/api/admin/simulator/*`, `WHATSAPP_SIMULATOR_ENABLED`                    |
| SIM-02    | Simulation uses the normal signed ingestion, durable jobs, role checks, tools, and database. Its histories/drafts are separate from real WhatsApp; replies and cross-recipient notifications are captured without Meta. Text and interactive replies are supported. | simulator ingress, `whatsapp_simulator` channel, durable outbox transport                     |

Deferred: owner/technician web dashboards (the simulator is an admin testing tool), payment collection, deposits, strict scheduling, attendance/no-show tracking, runtime locale switching, arbitrary WhatsApp avatar lookup, persistent customer image galleries, and simulator image uploads.
