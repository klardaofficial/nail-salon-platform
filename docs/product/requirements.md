ADMIN-01 acceptance: salon create/edit forms display opening and closing times, restore defaults for a new salon, and submit times as `HH:mm`. Resource selectors search by their displayed labels. The Bookings list keeps its compact columns and surfaces every other stored field — customer WhatsApp number, salon location, per-service custom/catalog detail, booked local time and timezone, additional request, cancellation timestamp/reason, check-in timestamp, and real-vs-simulator source — in an expandable detail row, and the matching CSV export carries the same fields so the table and export never diverge. The Overview page's recent-bookings list shows the customer's name (falling back to their WhatsApp number) and always shows the WhatsApp number as its own column; it does not show the salon, since each deployment has one configured business.

BOOK-11 acceptance: an organization's reminder-time list defaults to empty; there is no root/system default list of times. Each configured time is a whole number of hours or days before `starts_at`, stored as a single `offset_minutes` integer, and an organization may not configure the same resulting offset twice. Exactly one reminder message template applies to every configured time for an organization — never one template per time — resolved from that organization's own template if set, otherwise the root default, exactly like the technician confirmation/cancellation templates. The template body takes exactly two positional variables: `{{1}}` the customer's name and `{{2}}` the appointment time. When no reminder template resolves at either level, no reminder is sent for that organization and no plain-text fallback is attempted, because Meta rejects business-initiated messages outside the 24-hour customer-service window without an approved template; Organization Settings warns when times are configured but no template resolves. Reminders are delivered by a periodic scan (folded into the existing durable-outbox recovery cron rather than a separate scheduled function) that matches `confirmed` bookings whose `starts_at` falls within a small window of each configured offset; each `(booking, offset)` pair is delivered at most once via the same outbox deduplication key as other outbound messages, keyed on the offset rather than the reminder rule's row ID, so deleting and re-adding an identical time can never re-send or double-send.

CHAT-01 / BOOK-01 / TECH-01 date/time acceptance: every WhatsApp and Simulator conversation uses its configured `organization_settings.platform_timezone` for date interpretation, relative dates, booking times, staff date ranges, time off, and displayed appointment times. Replies, options, receipts, and app-generated notification parameters show dates and clock times without timezone names, abbreviations, offsets, or timezone explanations. New bookings snapshot the organization timezone; existing booking instants and snapshots stay intact, while conversation displays use the current organization setting.

CHAT-02 / SIM-02 recovery acceptance: an inbound history row alone never means processing succeeded.
