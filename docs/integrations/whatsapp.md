# WhatsApp integration

The callback is `GET|POST /api/whatsapp/webhook`. Meta's GET challenge must match `WHATSAPP_WEBHOOK_VERIFY_TOKEN`. POST reads the exact raw body and compares `x-hub-signature-256` with an HMAC-SHA256 made from `WHATSAPP_APP_SECRET` before parsing identity or data.

`normalizeWhatsAppWebhook` emits one event per text, image, interactive reply, or delivery status. Stored message events contain text, interactive IDs, MIME type, and WhatsApp media IDs, never downloaded bytes. Duplicate provider IDs return success without scheduling work twice. Status callbacks update delivery state and never produce a bot reply.

The webhook transaction writes `whatsapp_inbox_events` and `job_outbox`, then attempts an Inngest event. A two-minute recovery job redispatches pending/failed rows. The webhook responds quickly so conversational work and provider calls happen in background jobs.

Outbound capabilities:

- Text and image-by-media-ID messages.
- Reply buttons for one to three choices, with 20-character labels.
- One list section with up to ten rows, 24-character titles, and 72-character descriptions.
- Approved templates with body text parameters.

Free text remains valid after every control. More than ten active salons currently returns the first ten; future pagination/location search should reuse the same validated selection path.

Technician messages use `WHATSAPP_TEMPLATE_BOOKING_CONFIRMED` and `WHATSAPP_TEMPLATE_BOOKING_CANCELLED` when configured. Their documented body parameter order is confirmed: salon name, local appointment label, booking ID. Cancelled: booking ID. Without a template the adapter sends ordinary text, which succeeds only if Meta considers that technician's service window open. A customer's message does not open a technician's window.

Media processing fetches the temporary Graph URL with the access token and keeps the response in memory. Generated bytes upload directly to the WhatsApp media endpoint. The database stores the returned media ID so a delivery retry does not regenerate the image.

For local synthetic text ingestion:

```bash
pnpm whatsapp:simulate 4915112345678 "Hallo, morgen um 15 Uhr"
```

Use synthetic IDs only. The simulator signs the payload with the local app secret and posts to `APP_URL`; it does not bypass normal verification.
